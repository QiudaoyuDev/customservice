# 智能硬件客服原型基准与语言审计

日期：2026-08-17
范围：`opendesign/mockups/pilot-service-record/`

## 1. 审计结论

原型应被理解为一套“设备支持闭环”，而不是一个 AI 聊天页面。成熟度主要来自四件事：

1. 用户每次只处理一个问题，能够看到明确的下一步和最终结果；
2. 人工客服直接接收会话、设备、已做步骤、风险和服务时限；
3. 运营人员看到的是待审核信号，而不是自动学习的宣传；
4. 同一界面只使用一种语言，技术标识和本地化审核样例除外。

## 3. 从参考项目提炼出的界面原则

### 用户端

- 一次只提出一个判断，不同时展示多个后续步骤。
- 操作按钮必须直接改变流程状态，不能只弹出“已记录”。
- 正向结果、普通失败、人工交接和安全停止必须有不同收口。
- 切换语言后，整个用户会话使用所选语言，不在同一句中叠加翻译。

### 人工端

- 左侧是待处理队列，中间是当前工单和完整时间线，右侧是设备与处理依据。
- 系统事实、用户原话和系统推断必须区分。
- 接管、备注、结案和回流都是可执行状态，不是展示按钮。
- 工单状态使用“新工单、处理中、已结案”，不混用英文状态章。

### 运营与 POC

- 展示带口径的信号和验收门槛，不使用装饰性 KPI。
- 知识、流程、模型和提示词变更只进入审核与回归，不直接学习。
- POC 先限制客户、市场、型号、问题范围和流量，再按门槛扩量。

## 4. 语言规则

### 默认规则

- 当前演示环境默认中文，并在右上角提供全局“中文 / English”切换。
- 切换后导航、章节、字段、状态、按钮、提示和页面内容整体切换，不在一个页面混排两套语言。
- 中文页面中的章节、状态、字段、说明、按钮和提示全部使用中文。
- 不用英文小标题制造“国际化”观感。

### 可以保留英文或缩写的内容

- 品牌和项目名：Chatwoot、Dify、Flowise、Langflow、WhatsApp；
- 产品和版本标识：X100、rev.B、FW 2.1.0、EU；
- 行业标准缩写：Wi-Fi、CRM、API、SDK、MCP、POC、VPC；
- 工单、知识和流程编号：HAND-240817-38、KB-NET-102、wifi-check-01；
- 用户主动选择 English 后的完整英文工作区。

### 需要中英对照的唯一典型场景

产品、语言和当地客服团队审核同一句术语、保修或安全指令时，可以并列中文原意、en-US 和 en-GB。该对照属于内部本地化校对，不属于真实用户界面。

## 5. 页面级检查

| 页面 | 主任务 | 成熟度检查 |
| --- | --- | --- |
| 01 设备档案 | 确认具体设备和问题入口 | 设备上下文先于回答；未开放问题不进入假流程 |
| 02 诊断记录 | 运行受控状态机 | 正向、普通失败、人工交接和安全停止均可走通 |
| 03 人工接管 | 在保留上下文的情况下履约 | 队列、会话、设备档案、备注、结案完整 |
| 04 改进队列 | 把结案转为待审核信号 | 不暗示自动学习；指标带业务含义 |
| 05 海外 POC | 解释参考、接入、难点和通过线 | 中文分析为主；本地化校对区才中英并列 |

## 6. 后续原型变更门槛

- 新增的可见按钮必须有状态变化或明确结果。
- 新增英文文案前，先判断它是否属于专有名词、标准缩写、技术标识或语言校对。
- 新增企业接入能力应先落在适配层，不直接改动设备上下文、检索、状态机和交接包。
- 新增模型供应商应通过统一模型接口，并运行同一组离线评测。
- 桌面与 390px 宽度下不得存在真实横向溢出。

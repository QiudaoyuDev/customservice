# 首个 MVP 修复与交付计划

## 目标

按“运行基线 → 接口契约 → 黄金链路 → 诊断与人工交接 → 运营与发布验收”完成首个可交付 MVP。以后端 REST 契约为唯一标准，不保留错误路径的兼容层。

## 已确认决策

- 前端项目级 `.npmrc` 固定使用 npmjs 公共仓库，不修改用户级 npm 配置。
- 首期人工交接使用内部客服队列；SMTP/外部工单只保留后续适配边界。
- 保持 React 单前端和 Spring Boot 模块化单体；不扩展语音、退款换货、远程控制和多渠道工单。

## 实施顺序

1. 建立可复现构建，修复前后端接口、multipart、SSE 与错误响应契约。
2. 打通“产品和二维码 → 文档发布 → 扫码会话 → 有依据回答 → 用户反馈”的黄金链路。
3. 补齐产品、二维码、文档和流程的最小维护能力，移除管理员手填 UUID 的主要路径。
4. 将诊断流程发布为不可变版本，固定会话使用版本，并确保高风险、拒绝和失败可靠转人工。
5. 建立带交接包快照的内部人工队列、匿名会话令牌、上传防护、国际化和业务事件。
6. 补齐最小统计与评测能力，并完成自动化、真实浏览器和依赖降级验收。

## 验收原则

- 每阶段运行后端测试、前端 `npm ci && npm run build` 与 `git diff --check`。
- 不以静态检查替代 MinIO、Qdrant、OCR、模型或真实浏览器集成验收。
- 任何事实回答必须带有效知识引用；无证据、模型失败、冲突或安全风险必须明确降级或转人工。

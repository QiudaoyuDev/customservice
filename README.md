# 出海硬件厂商的多语言 AI 售后诊断与客服平台。



面向出海硬件厂商的设备售后诊断与知识运营产品方案。

通过二维码识别设备型号、地区及版本，在受产品上下文约束的知识范围内提供多语言售后支持；当证据不足、存在安全风险或需要处理保修与退款时，系统将完整上下文交接给人工客服。

普通知识库只能回答“遥控器怎么配对”；你的产品需要进一步解决：

- 当前用户使用的是哪个型号、硬件版本、销售区域和固件版本；

- 用户看到的故障现象是什么；

- 应该依次检查什么；

- 每一步检查结果会进入哪个排障分支；

- 哪些操作存在断电、拆机、触电、数据丢失等风险；

- 什么时候应该停止 AI 排障并转人工、换货或返修；

- 如何把 AI 已经收集的信息完整交给人工，避免用户重新描述一遍。

因此，真正的产品壁垒不是模型，也不是聊天页面，而是下面三部分：

- 产品级知识体系

- 结构化故障诊断流程

- 真实客服数据形成的持续优化闭环

## 产品目标

- 为硬件厂商提供 7×24 小时、与具体型号和版本匹配的售后支持。
- 用可执行的故障诊断流程替代泛化的 FAQ 问答。
- 将说明书、错误码、维修记录和专家经验沉淀为可审核、可追溯的知识资产。
- 通过人工接管和安全规则，避免错误指引与高风险自助操作。

## 核心能力

- 设备识别：二维码绑定租户、型号、地区及可选批次或序列号。
- 受限检索：按型号、硬件版本、固件版本、地区和有效期过滤知识。
- 分步诊断：针对高频故障提供带分支、预期结果和停止条件的排查流程。
- 人工协同：自动附带对话、已尝试步骤、错误码、图片和引用知识进行转接。
- 知识运营：支持文档解析、审核发布、回滚、过期提醒和质量指标分析。

## MVP 建议范围

以一家试点厂商、一个硬件品类和一个产品系列为起点，支持二维码绑定型号、文字/图片对话、文档知识库、高频故障流程及一种人工转接渠道。首期不包含自动退款换货、自动远程控制和未经审核的知识自动发布。

## 当前状态

本仓库已包含本地基础设施部署基线：PostgreSQL、MinIO、Qdrant、本地 OCR 与本地 Embedding/Rerank 服务均通过 Docker Compose 管理。

初版业务代码位于 `backend/`（Java/Spring Boot）与 `frontend/`（React/TypeScript）。本轮的范围与决策记录见 [初版开发记录](./docs/2026-07-28-initial-development-plan.md)。在配置 JDK 21、Maven 3.9+、Node.js 和 `infra/.env` 后，可分别在两个目录执行构建；正式运行前必须设置 `BOOTSTRAP_ADMIN_PASSWORD`、`JWT_SECRET` 和各存储密码。

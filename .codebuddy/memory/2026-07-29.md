## CI 防回归：i18next-scanner + missingKey 告警

为防新串漏翻接入 CI 门禁：

- `i18n/index.tsx` 增加 `missingKeyHandler`（首参类型为 `readonly string[]`，注意与旧 `string` 签名不兼容，曾导致 `tsc` 报错 TS2769），DEV 下 `console.error('[i18n] Missing translation: ...')` 运行期告警；动态键由 `statusLabel`/`regionLabel` 拼接 `status.`/`regions.` 前缀兜底。
- 新增 `scripts/i18n-lib.mjs`（共享：用 esbuild 把源文件转成纯 JS 去注释/类型再交给 scanner，避免注释里 `t('a.b.c')` 误扫与 TS `as` 触发 esprima 报错；`func.list` 必须含 `t` 才能扫到 `t('key')`）、`scripts/check-i18n.mjs`（门禁：源码静态 key ⊆ en ⊆ zh，并对 `_one`/`_other` 复数后缀做基础键兜底）、`scripts/scan-i18n.mjs`（生成 `.i18n/extracted-keys.json` 报告）、`i18next-scanner.config.js`（standalone CLI）。
- `package.json` 增加 `scan:i18n`/`check:i18n` 脚本，并显式声明 `esbuild` devDependency。
- `.github/workflows/i18n-check.yml` 在 frontend 变更时跑 `npm run check:i18n` + `npm run build`。
- 补齐了扫描暴露的真实缺失键：`flows.create`/`flows.highRisk`/`qrs.create`/`qrs.newTitle`/`handoffs.resolutionLabel`（原 `handoffs.resolution` 已是对象，字符串标签改名避免 i18next 键冲突），以及 `documents.chunks`/`flows.stepCount` 的 `_one`/`_other` 复数形式。
- 验证：`npm run check:i18n` 通过（298 个静态 key，en/zh 一致），`npm run build` 通过（exit 0）。
- 关键坑：`i18next-scanner` 默认 `func.list` 为 `['i18next.t','i18n.t']`，本项目用 `t()` 必须配置含 `t`；扫描前务必用 esbuild 去注释/TS，否则误报。
